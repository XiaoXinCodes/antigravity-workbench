# 图片目录诊断可见性修复

基线：`943b83f6117020a48302d9f353ccd0811db842af`，分支 `fix/image-catalog-diagnostic`。命令显示名保持“Antigravity Workbench: 诊断当前账号图片目录（不生图）”。

## 确定的原因

原 `src/debug-ui.ts` 在调试模式关闭（默认状态）时直接返回；原回归甚至明确期望调用命令后零查询、零输出。开启模式后仅调用工作台 refresh，没有 reveal；结果位于持久折叠的“运行环境与文件位置”，工作台尚未打开时 refresh 也没有可更新视图。命令注册和显示名称正确，已安装入口 SHA 为上一候选的 `7a82e6482f4f5afba0c2f9a2434d3bc3ecfcdbe9f11e116019c701bc18120e6e`。这足以解释无输出，并非 Pro 权限证据。

## 修复

诊断不再依赖日志开关或日志目录可用性。点击先保留查询中状态，再通过官方 WebviewView.show / 注册视图 focus 显示工作台，展开结果区域并滚动至内联结果；冷启动直接由状态生成 HTML，不依赖 ready 时机或一次性消息。只有成功显示视图后才查询。视图显示限时 5 秒，失败显示一个脱敏错误提示且不查询；目录查询限时 60 秒，失败和超时显示内联终态。结果保留本窗口内存，关闭视图不自动重开；下次打开恢复状态。重复点击与未完成取消保持单飞，底层仍未停止时不启动新请求；扩展释放时取消并丢弃结果。既有同账号、端点和凭据版本核验保持原实现。

## 安装与原窗口边界

检查的受支持 UI 接口没有原生窗口或浏览器可操作。WSL 安全日志中有 2026-10-06 23:46:28.971 的插件 onView 激活记录，但没有原窗口身份或实际加载入口 SHA，不能证明原窗口已经重载。发现本地会话有一份已保存草稿，仅提取草稿存在性与数量，未输出正文；未保存编辑无法从原生 UI 核验，因此本轮不自动重载或退出窗口。磁盘更新与逐文件校验另记录在任务目录的 `catalog-visibility-install.json`，不把磁盘匹配当作激活成功。

本轮没有真实目录请求、生图、付费推理、切号、新 OAuth、凭据正文读取、上传、push 或 release。真实 Hub / 同账号直连目录对照仍待原窗口激活修复后明确触发。结果入口：命令面板运行上述命令，通过命令面板“高级排障…”选择图片目录诊断，结果显示在工作台按需出现的独立诊断区域，无需开启调试。
