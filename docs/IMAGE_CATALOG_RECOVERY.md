# 图片目录刷新与账号比较移除

本候选删除图片页的“比较此模型的账号额度”、跨账号推荐卡片和使用推荐账号按钮，以及专用控制器、候选查询和中英文文案。图片账号选择、“查询额度”、历史、收藏、结果版本比较、工作台多账号额度总览及定时任务保持原有用途。没有新的命令或设置迁移，不清理用户记录。

## 独立目录问题的证据

对上一候选 `12d8b1a` 的九个本地 mock 对照确认：生成成功后，期间的当前身份通知可排队再查目录；目录失败仍保留成功图片与历史，但共用“没有提交图片”文案会误导。第一次同范围身份通知在完成后还会先清空目录，导致失败后失去上次展示。当前账号的锁冲突也可能被归成 `IMAGE_SAVED_MODELS_FAILED`。单独额度查询失败不会将任务改为失败；独立图片账号不受无关官方身份通知影响。

实机提供的成功操作记录只有 HTTP 200 和已保存图片，未记录相应目录错误。无法据此断定用户看到提示的精确时间、实际目录 HTTP 状态或是否发出了目录网络请求。删除账号比较本身不修复这些独立问题；本候选另行修复目录刷新逻辑。

## 本候选的行为

- 无关的同范围通知只更新展示，不清空目录、不排队重复查目录。已有检查由原请求完成；超过五分钟的展示、身份恢复或实际账号／端点变化仍核验。
- 同账号、端点目录查询失败保留模型、原选择、来源时间及成功产物；显示目录检查错误和旧数据，阻止将旧展示当作发送资格。成功刷新可恢复；成功空目录仍反映服务端移除。
- 保存账号缓存继续按身份指纹、端点和加密记录修订隔离，并在锁内核验修订；上限五分钟，受令牌有效期限制。当前账号复用目录前重新绑定身份和项目，以身份指纹、subject、额度身份、Hub 代际、端点、精确加密记录修订以及令牌／项目的内存哈希匹配，核验后才复用，且受五分钟及令牌有效期限制。当前目录缓存只存公共目录数据；保存账号原有凭据缓存仅存在扩展宿主内存中，不另行持久化凭据。
- 展示记录增加可选的有界修订号，兼容旧缓存；同一宿主保留已成功写入的较新条目，旧存储通知不能抹掉选择或用途确认，较新的其他窗口写入仍可更新。此修订不作为凭据或模型角色证据。实际 UI 检查发现确认已写入／回读后被下一次旧目录保存抹掉，新增旧回显、明确取消确认及较新外部编辑的回归。
- 主动“重新检查”、额度查询及每次实际生成前仍要求新鲜目录；disabled、移除和用途校验不被缓存或用户旧选择绕过。目录缓存命中也可能执行身份／项目网络核验，不能理解为所有 Google 请求都被省略。
- `fetchAvailableModels` 是向所选 Google 服务端点查询账号模型目录，不是图片生成。成功生成后会保留对同一模型的额度查询，该查询也读取新鲜目录。锁冲突可能在网络前发生。不会自动重试图片生成。
- 目录诊断使用独立 `image.catalog` 操作，记录固定阶段、失败类别、缓存命中、端点及合法 HTTP 状态，区分锁、绑定、HTTP、网络、TLS、超时和解析。沿用默认关闭的诊断开关；不记录 token、邮箱、项目原值、提示词或响应正文。图片生成记录不混入后续目录失败。

验证只使用合成身份、合成图片结果和注入传输，外部网络阻断。不读取用户凭据，不进行真实 Google 目录或模型请求。完整检查、隔离 VS Code UI 与包／源码一致性结果随候选收据交付；Windows／WSL 的实际 Hub、凭据轮换与真实服务返回仍需用户选择的实机验收。
