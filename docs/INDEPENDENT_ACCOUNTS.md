# 多账号管理

Workbench 可以保存多个 Google Antigravity 登录，在账号卡片中切换、刷新配额和移除本地副本。账号属于保存它的扩展宿主；Windows 和 WSL 的保存位置彼此独立。

## 添加与保存

| 入口 | 结果 |
| --- | --- |
| 添加账号（OAuth 登录） | 在浏览器完成授权，保存新账号，再恢复添加前的登录状态；不会自动切到新账号 |
| 在官方插件直接登录 | 核验并显示新的当前身份，自动保存同宿主副本，不发起额外 OAuth，不恢复旧登录 |
| 保存当前 | 保存当前已登录且经核验的官方账号，不重新发起浏览器登录 |
| 导入 | 从加密迁移包保存所选账号，不改变当前官方登录 |

添加过程中需要使用官方登录组件。插件会先明确提示将停止的后台与本窗口任务范围，确认后主动处理，再恢复原登录并核验；活动任务可能被中断。原来未登录时，添加完成后仍恢复为未登录。添加完成后想使用新账号，再点击对应卡片的“切换”。详细浏览器流程见 [OAuth 登录](DIRECT_LOGIN.md)。

## 使用账号卡片

- **切换 / 使用中**：切换到这个已保存账号；当前账号显示“使用中”。完成组件重启及服务端身份核验后才显示成功。
- **刷新**：查询这个账号的服务端配额，不要求先切换；显示同步时间、剩余额度和重置时间。
- **取消查询**：请求取消当前配额查询。授权更新已经提交时，可能需要先完成安全保存再结束。
- **移除**：非当前账号仅删除本地副本。当前账号先安全切换至列表中首个本地凭据可用的同宿主其他账号，核验成功后删除原副本；切换失败保留原副本。没有可用替代时保持官方登录，不撤销 Google 授权。同一当前身份不会被后台立即重新添加；身份改变后解除抑制。

“当前”标记来自经服务端核验的官方身份与保存账号的匹配，不以列表顺序推断。返回窗口立即检查，空闲时每五秒从本机 Hub 探测候选变化，再核验并自动保存；相同身份保留账号 ID 与标签。自动保存失败不会抹掉已核实身份，可用“保存当前”重试。

## 未完成操作

切换需要安全备份原登录并核验目标身份。遇到未完成操作时，工作台显示“重新检查登录”或恢复入口；根据提示继续，其他冲突操作暂时不可用。不会因一次错误提示就清除原登录备份。
