# 服务端配额与刷新

账号卡片上的“刷新”按需查询该账号的服务端额度，不需要先切换当前官方登录。结果包含模型或分组、剩余比例、重置时间和最近同步时间，以服务实际返回的字段为准。

## 第一次查询

1. 找到保存在当前宿主中的账号，点击“刷新”。
2. 点击刷新即请求该账号的查询及必要授权更新；查询进度、结果和错误直接显示在此账号卡片，不额外弹出确认或成功提醒。
3. 等待卡片显示结果。正在查询时可点击“取消查询”；错误直接显示在对应卡片。

这是按需查询，不是后台持续轮询。上次结果会标明同步时间；请求失败不会把旧结果标成刚刚成功获取。某些字段未返回时保持未知，不补造额度或重置时间。

## 当前账号与其他已保存账号

已核验的当前账号优先使用官方后台查询。其他已保存账号使用各自已保存的授权查询身份和配额；插件不为查询而切换当前官方账号，也不改写其登录槽。

支持且已授权的登录在过期或返回未授权时，可进行一次受约束的授权更新，核验服务端身份后保存返回值。服务端已撤销授权、不支持的账号类型或无法确认来源的副本会要求重新授权，不会探测其他客户端或轮换账号。

授权更新已经提交后取消，可能需要先完成有界核验与保存，因为服务端可能已轮换令牌。同一授权若被多个客户端复用，远端轮换也可能影响其他客户端；它不等于普通只读缓存刷新。

## 如何理解结果

| 提示 | 含义 |
| --- | --- |
| 服务端查询、同步时间 | 对应账号最近一次成功返回的结果 |
| 上次结果 | 保留的历史显示，不代表刚刚查询成功 |
| 需要重新授权 | 按“添加账号（OAuth 登录）”重新授权并保存 |
| 待核验或更新结果不确定 | 先处理未完成核验，避免再次发起授权更新 |
| 没有额度数据 | 服务端未提供可展示结果，不等于剩余额度为零 |

额度信息不是对下一次请求成功的保证。容量、速率、账号资格或服务策略可能独立影响图片和其他调用。
