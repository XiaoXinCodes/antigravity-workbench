# 本机双账号验收

不需要将两个账号导出给开发者。账号包、密码、token、SecretStorage 数据库及官方原始日志都留在自己电脑。使用有权管理的 A、B 两个测试账号，结束当前 Antigravity 任务并保存工作。

1. 保持 A 为当前官方账号，在 Workbench 保存当前登录
2. 点“添加账号（OAuth 登录）”，在 Google 页面授权 B。等待官方组件重启并核验原登录已恢复；B 应出现在保存列表，当前官方账号仍为 A。不要把“已保存 B”误认为“原登录已恢复核验完成”
3. 当前仍为 A 时，分别查询 A 与 B 配额。首次仅确认本机令牌向 Google 官方查询的范围；结果必须各在自己的卡片。查询前后当前官方账号仍为 A
4. B 的访问令牌过期时，应自动刷新该保存副本，再显示 B 的额度；不能显示 A 的额度或自动切换到 B。取消刷新时应先安全保存已返回的轮换令牌。Google 撤销授权或配置不支持时才提示重新登录；重新添加会产生新的保存副本，确认新副本可用后再移除旧副本
5. 点 B 的“切换到此账号”，确认本次写入与组件重启。无需再点“确认成功”，程序应自动完成服务端身份核验。切回 A 重复一次
6. 添加账号时取消一次授权。应该恢复原登录并自动核验，不能留下新账号被当成当前账号。若恢复失败，保留当前状态，用内联恢复入口，不删除官方文件或密钥库
7. 保持同一个项目，检查原有两条对话与一张已有图片。这里只检查，不移动、删除或重建历史
8. 验证卡片上直接有“移除”，只移除保存副本，不退出当前官方账号
9. WSL 必须在对应发行版独立验收。文件模式已核验时不要求未使用的系统密钥库；未核验存储路由时应安全停止，不能复制 Windows 凭据规避
10. 命令面板运行“导出本机验收结果（不含账号凭据）”，保存一个新的 JSON 文件。可以分享此文件，加上哪一步失败和固定错误文字。文件不会上传，保存目标已存在时不会覆盖

导出的事件仅证明本机实际记录了那些操作，不代表全部检查都通过，也不记录 A/B 真实身份。配额数字、账号邮箱和图片内容无需发给开发者。真实付费图片生成另行由本人确认；本验收不自动发起模型推理。
