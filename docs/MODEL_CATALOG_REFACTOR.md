## 数据缺口与兼容决策

- 现有协议证据只有 `models` 的原始 key、`displayName`、`disabled`、`model` 枚举、`quotaInfo`，以及 `imageGenerationModelIds`、`agentModelSorts[].groups[].modelIds`。不调用 Google 获取真实账号样本；不把合成 fixture 冒充服务端实测。
- `supportsImages` 是输入能力，不能推导图片生成；推理名称/后缀不授权 thinking 参数。没有可靠的推理参数协商字段，因此不自动添加 reasoning 参数。
- agent 分组可包含图片成员；显式图片清单优先确认图片角色，该成员绝不进入普通请求。目录没有声明用途的项保留可见，必须明确确认用途才能请求；此确认不是服务端能力或权限证明，不覆盖 disabled / 明确相反角色。
- 显式图片能力继续支持现有图片生成、参考图与批次流程。比例/尺寸是用户显式协议选项，不声称每个模型都支持；明确否定图片输入的记录拒绝参考图。目录未提供参数能力时不猜型号。
- 可选 `model_enum` 缺失时省略，不再伪造。离线无法证明真实服务端是否接受省略标签，必须列为实机验收项；不得为了“可用”偷偷恢复具体型号兜底。
- 目录缺项/失败不证明无权限；不伪造配额。新目录只替换同范围成功展示，不清除已有用户 ID。旧展示不是新请求授权，发送前重新核验，拒绝晚到身份/端点响应。
- 保留扩展 ID、MIT、现有账号/图片/历史格式、0.1.11 最近成功额度读数。新用途确认以可选字段迁移，不把旧任务静默确认为未知能力。

## 最终实现与升级行为

`model-catalog.ts` 负责唯一的目录结构、用途、输入能力、禁用和每模型额度解释；图片、定时、额度和诊断只读取其投影。模型 ID 的边界校验也共用一处。保留原始 ID 和安全的服务端 displayName；不加入名称别名或推理参数猜测。账号额度按服务端 groupId 分组，用户收藏仍可优先排列；没有 groupId 的额度保持未分组。

`model-catalog-display.ts` 将有界展示、原选择和未知用途确认按账号身份指纹、已核验 subject / quotaDisplayId、端点及用途隔离保存。展示不保存令牌，也不作为发送资格证明。相同范围查询失败保留上次展示、时间和选择；成功空目录反映移除，但缺失的原选择仍保留并阻止发送。账号替换、端点切换及晚到响应不会覆盖新范围。普通选择和图片选择都可按范围恢复。

图片目录刷新错误、有效缓存与图片账号比较移除的后续修复见 [目录恢复说明](IMAGE_CATALOG_RECOVERY.md)。

未知用途确认仅显示在所选未知模型旁，按范围记忆；已知模型不增加弹窗。已有图片消耗确认保持一次。已有任务保留 ID、时间表及开关字段；只有用途未知的任务需要编辑并确认后才能再次发送。新的显式图片分类或 disabled 会使先前普通用途确认失效于发送校验。

- Node 22、Linux：`npm run check`（AST、TypeScript、ESLint、完整单元及集成测试）；1,520 项测试中 1,516 通过、0 失败、4 项 Windows 条件测试在 Linux 跳过。完整日志随候选保存。
- Python：许可证 8 项、发布安全 34 项、打包文档 5 项通过。发布安全测试只使用模拟器，没有执行发布或远端分支操作。
- VS Code 1.141.0 独立用户目录：扩展激活、额度含 Reload Window（36 检查）、全局语言（10）、普通定时请求（34）、高级触发器（10）、历史、账号选择、所选账号额度与双语目录失败恢复（13）通过。图片页截图交互额外验证未知用途内联确认、刷新记忆及中英文切换。
- Chromium：36 个布局/交互场景通过；保留窄栏及中英文实际 VS Code 截图。所有 UI 账号、额度和请求均为合成适配器。
- 回归覆盖：随机更名的 60 组陌生 ID / 误导名称、最终图片及普通请求的原始 model ID 与参数、增删/改名/禁用、缺失/矛盾能力、包装目录、独立生图账号、身份与端点隔离、查询失败/刷新/晚到响应、旧任务迁移。`check:models` 使用 TypeScript AST 检查静态模型标识、默认值/映射、名称推断及目录解释边界，包含故意引入回归的反例测试；不是只删字符串的 grep 检查。
- 初次摸底时，旧测试 fixture 没有拦截本次新增的元数据路径，出现使用虚构 token 的失败 Google 元数据连接尝试。发现后停止该轮，补齐 mock，并为测试及隔离宿主加入 HTTP/HTTPS/fetch 外部请求阻断。没有读取用户真实凭据，没有成功真实生成调用；后续正式验证均在阻断下运行。不能将整个任务表述为“从未尝试外部连接”。
- 默认沙箱将安全文件系统测试目录呈现为不同所有者，导致无关安全断言失败；正式验证在已授权的云端原生文件权限环境运行，没有放宽生产权限检查。

候选继续使用版本 0.1.11 与 `xiaoxincodes.antigravity-account-manager`，由独立分支本地提交构建，不推送、发布或安装用户本机。候选、源码 ZIP、提交与 SHA-256 / 逐模块一致性记录放在 `artifacts/`；该目录不进入 VSIX。MIT、许可附件、历史 changelog 和 LinuxDO 事项保持不变。

## 仍需实机验收

1. 用实际账号对照 Daily / Production 的目录字段，确认服务端对 `imageGenerationModelIds`、agent 分组、disabled、supportsImages 和 model 枚举的当前契约；合成测试不能代替这一步。
2. 验证省略缺失 `model_enum` 及删除推断标签 `used_claude` / `used_claude_conservative` / `used_non_gemini_model` 后，服务端仍接受图片请求。仓库没有证据证明这些标签必填，也没有离线证据保证省略后所有端点均接受；候选不恢复型号特例。
3. 经用户另行授权后验证实际生图、参考图、尺寸/比例和普通定时请求。目录未协商逐模型参数范围，当前保留用户显式协议选项；不保证每个模型接受所有尺寸，不自动添加推理参数，不伪造额度。
4. Windows / macOS 的原生存储、当前官方账号与独立图片账号、真实升级及 Reload Window 仍需各平台实机验证。本轮只有 Linux 隔离 VS Code；4 项平台条件测试跳过。
5. 包内文档按构建提交固定链接。本地未推送提交的 GitHub 链接在发布前不会在线可用；随附源码 ZIP 提供完整本地文档。
