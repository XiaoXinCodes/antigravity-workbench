# 额度查询结果的持续显示

基线：main `03ee3a80c89a1295e77efc865bbf438a2102f96a`，修复初次以本地 `0.1.10` 候选包验证，正式版本为 `0.1.11`。

## 原因与修复

- 图片页 `accountStateChanged` 原先因任何全局账号状态变化而清空额度，包括官方账号 A 的核验变化，而图片页独立选择的是 B。现在按选中账号、模型、端点及账号修订隔离请求；无关账号变化保留数值，当前身份暂时未知时保留旧读数并继续禁止相关操作。
- 账号卡片原先把 `capturedAt` 同时作为请求修订与显示身份。同一账号的凭证重新捕获会更新时间，导致额度、历史记录和置顶项消失。新增 `quotaDisplayId` 只用于读数、历史与置顶的归属，正常同身份捕获保留它，明确替换重新分配它。原有请求、凭证、图片任务、推荐和自动任务校验继续使用严格修订。
- 宿主或图片控制器重建原先没有成功读数可恢复。新增独立私有 `quota-display/state.json`，只保存白名单额度字段、查询时间及不透明身份摘要。采用现有私有文件与跨窗口锁机制；旧响应不覆盖新时间，删除或替换后的延迟写入被拒绝。

对应实现：`src/quota-display.ts`、`src/quota-observation.ts`、`src/live-switch.ts`、`src/live-ui.ts`、`src/direct-image-ui.ts`。历史与置顶兼容在 `src/quota-history*.ts` 和 `src/quota-preferences.ts`。

## 状态转换

| 事件 | 显示 | 可执行操作与时效 |
| --- | --- | --- |
| 精确当前查询成功 | 数值与实际查询时间 | 继续使用原有 60 秒新鲜度规则 |
| 60 秒到期 | 数值保留，标为旧数据 | 不更新时间，不当作实时额度 |
| 同账号刷新失败或取消 | 保留成功值，同时显示失败状态 | 不把旧值升级为新查询 |
| 官方身份暂时未知 | 同归属旧值可读 | 官方当前账号操作仍被阻止；独立 B 选择不会被 A 的核验抹掉 |
| 普通同身份凭证重新捕获 | 读数、历史和置顶保留 | 请求修订仍变化；恢复读数明确为历史值 |
| 图片关闭重开或宿主重建 | 恢复精确账号、模型、端点的成功值 | 一律为历史值；不据此授权或自动请求 |
| 账号删除、明确替换、已知主体变化、宿主归属变化 | 旧归属不可继承 | 迟到完成不能给新归属填值 |
| 缓存损坏、不安全或写入失败 | 当前成功查询仍可显示 | 不阻止账号操作；不能保证下次重建恢复 |

恢复读数不作为目录已查询完整的证明，不写成新历史采样，也不触发额度提醒。推荐仍要求精确、成功、足够新的查询；没有启用定时模型请求。缓存最多 50 个账号读数、500 个图片读数、每账号 200 个桶，并以 1.5 MiB 为上界优先保留较新的记录。此限制不改变当前窗口刚查询成功的内存显示。

旧历史和置顶指纹可沿用原始捕获时间；明确替换获得新 UUID，不能匹配旧时间身份。已有版本没有持久额度文件，本次升级不能找回此前已丢失的内存结果，需要在修复版本里成功查询一次。
