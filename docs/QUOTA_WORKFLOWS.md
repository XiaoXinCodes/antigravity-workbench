# 额度总览、历史与定时请求

## 比较多个账号

账号卡片的“刷新”查询对应账号的服务端额度，不需要先切换登录。在额度总览搜索账号，选择同一模型或额度项后，可按剩余额度从高到低、从低到高、最近更新或最近重置排序；也可恢复保存顺序。比较项与排序会在重载后保留。

“批量刷新”逐个查询当前宿主中的账号并显示进度，可随时取消。刷新保留卡片的滚动、焦点和折叠状态。未查询、失效、未知或旧结果不会被当作新鲜的零额度，也不会据此推荐账号。

用星标收藏常用模型，按家族折叠其他项。家族只是显示分组，不表示不同模型共享同一个额度池。点击“快速查看额度”打开原生 QuickPick；在卡片或快速选择中将一个账号／模型置顶后，状态栏显示它的额度，点击可回到快速选择。

## 额度历史

打开“额度历史”，按账号、普通额度项或图片模型、时间范围筛选，查看观察点与明细。记录来自实际查询；未知和失败保留对应状态，不插值推算额度。可以设置保留天数、清理当前筛选范围或清空历史。

## 图片账号比较与历史复用

图片工作室可跟随当前登录，也可独立选择已保存账号。在所选模型下比较账号时，只使用同一服务端点、精确模型 ID 对应的额度；其他图片模型或普通模型的额度不代替它。未知、旧数据和不可用结果会明确标记。选择图片账号不切换官方登录。

从历史任务复用请求参数时，会恢复原模型、提示词、比例、尺寸等已保存参数。缺失参考图会提示，需检查并补齐后再提交；模型仍须在当前所选账号的目录中可用。继续修改已有结果时保留原图，可以比较不同版本或将产物用进项目。

## 提醒与定时请求

从工作台打开“管理定时请求与提醒”。低额度、耗尽和恢复提醒均默认关闭；开启后，后续新鲜查询出现状态变化才提醒，首次观察只建立基线。提醒本身不发送普通模型请求。

定时请求总开关和新建／编辑后的任务默认关闭。选择账号、从它的目录选择普通文本模型、填写时区，再预览计划并明确启用。目录类型未标明时，需手动选择并确认这是普通文本模型，不要选择图片生成模型。对话服务端点位于折叠的高级设置中，日常使用保留默认即可。

| 方式 | 设置与行为 |
| --- | --- |
| 日／周 | 填写当地时间和星期；选择全部星期即每天运行，可在一天设置多个时间 |
| 间隔 | 1–1440 分钟，指定含时差的起始时刻，按实际经过时间运行 |
| 五字段 cron | `分 时 日 月 周`，支持列表、范围、步长和月份／星期缩写；例如 `0 8 * * 1-5` 为所选时区的工作日 08:00 |
| 服务端满额恢复 | 每 15–1440 分钟检查一次；首次建立基线，只有新鲜观察从未满变为精确 100%，且发送前再次确认满额，才触发请求 |

计划使用所选 IANA 时区。日／周和 cron 在夏令时缺失时刻跳过、重复时刻只取较早一次。cron 不支持秒／年字段、`L/W/#` 或宏；满额恢复不按倒计时或接近 100% 推断。

请求固定发送短输入 `Hi`，输出预算默认 8 token，可设为 1–64；这不是总费用上限。首次实际发送需确认额度／费用授权。支持手动测试、暂停、取消、删除与结果查看；已发送的未知结果不会自动重试。

VS Code 扩展宿主必须保持运行。暂停或关闭期间延误超过 5 分钟的计划会跳过；定时请求不会自动切换官方账号。模型是否可调用、实际消耗及服务端额度变化仍以服务端结果为准。
