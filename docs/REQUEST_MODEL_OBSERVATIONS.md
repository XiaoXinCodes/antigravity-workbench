# Request model observations (candidate for 0.1.12)

The workbench records raw server model declarations; it cannot verify underlying weights or prove that an advertised backend actually served a request. No model aliases, pricing tables, catalog/display-name joins, cross-row fill, proxy or additional inference request are used.

## Available paths

- **Official CLI / IDE local conversations:** the workbench's **Model and token records** button opens an on-demand reader. **Read local records** discovers official CLI / IDE conversation directories on the current extension host when clicked; directory/file pickers are fallback options. Nothing is discovered or read at activation or panel opening. Discovery is bounded to the 20 most recently modified UUID databases (5,000 directory entries per source) and 2,000 generation rows per read, with explicit limited/skipped scope and fixed reason counts (changed, unsupported schema/data, unsafe, unavailable, file size limit). File mtime only selects files; it is not a generation timestamp. Windows UI hosts in WSL workspaces cannot scan Windows home as WSL data; they must run in the native WSL extension host. The selected database's `gen_metadata(idx,data)` is decoded per generation, with response identity used only for deduplication. Data stays in panel memory and is cleared on close; reading again replaces the list. CLI usually uses `~/.gemini/antigravity-cli/conversations`, IDE `~/.gemini/antigravity/conversations`; the CLI directory respects GEMINI_CLI_HOME. Unknown schema/fields remain explicit. **Requested model field number is unverified and therefore not implemented**: it displays Not provided with an explanation. Display label #21 is ignored.
- **Existing direct image requests:** task details retain requested ID and one returned observation for each attempted batch HTTP response. Root `model`, `modelVersion` and wrapped `response.model`, `response.modelVersion` are inspected independently. Transport failures have missing response metadata. No additional account/project/catalog/generation request is introduced by this feature.
- **Existing wake requests:** instance details show requested ID and the same raw fields across SSE frames. Distinct declarations are retained as conflicts rather than overwritten; an interrupted stream preserves declarations already received. No additional scheduled run or probe is introduced. Old records without optional metadata show Not provided.

Different declared strings, including differing root/wrapped/version fields, are marked conflicting declarations; this is not proof of routing failure. Sources remain associated with their raw values. Missing/invalid/conflicting fields are separate. At most two summary values and ten field/value declarations are retained per response; overflow is marked. Invalid field values are not echoed.

## Local fields and token semantics

Field meanings are based on public reverse engineering, not a supported Google schema. The independently implemented bounded wire reader consumes root #1 (chatModel), chatModel #19 (responseModel), and chatModel #4 (usage). Unknown wire fields are skipped, not inferred.

| Display | Usage wire fields | Rule |
| --- | --- | --- |
| Uncached input | #1 system + #2 newly processed input | Both must be provided; no cache-read double counting |
| Cache read input | #5 | Separate from uncached input |
| Text output | #9 | Separate component |
| Reasoning output | #10 | Separate component |
| Total output | #3 | If absent, derive only when both #9 and #10 are explicit; inconsistent totals are conflicts |

Missing protobuf scalars are missing, including omitted zero-like proto defaults: no guessed zeros. Total output already includes text/reasoning and must not be added again. No cost or aggregate/trend is shown. #11 response identity is hashed for same-session deduplication; mismatched duplicate values produce conflicts. No account attribution, mtime-based generation timestamp or cross-session grouping is inferred.

Frozen evidence: [Tokscale Antigravity generation parser at 4f17d6c](https://github.com/Javis603/tokscale/blob/4f17d6c6d85f5582949dcb0476c55518eafd7e23/crates/tokscale-core/src/sessions/antigravity_cli.rs#L1-L60). This documents six sessions / 140 turns and optional #19; it does not establish a requested-model wire field. Runtime code is an independent TypeScript implementation; no upstream Rust code or runtime library is bundled.

## Safe snapshot and limits

The reader opens source DB and optional WAL with read-only file handles, never opens source SHM and never connects SQLite to the original path. It checks ownership, regular-file type, no links, handle/path identity and size/mtime/ctime before and after copying. Nonempty rollback journals or changing snapshots fail closed. On-demand directory imports retry changed snapshots once, sequentially; every attempt uses and cleans its own private snapshot. It copies DB/WAL bytes to a private 0700 temporary directory (0600 files), queries **only** gen_metadata in a bounded, cancellable worker, closes and removes the copy. The worker detects built-in `node:sqlite` at runtime; older hosts use the packaged sql.js 1.14.2 WASM, with no Python, downloads or native ABI modules. WASM replays only complete committed WAL transactions after checking page size, salts and cumulative checksums, then reads a self-contained private memory image. Invalid frame tails end recovery at the last valid commit, as specified by SQLite; invalid WAL headers fail closed. SQLite may touch only the private copy's SHM. Raw prompt tables are not decoded, queried, emitted or persisted, although database bytes necessarily pass through the temporary file snapshot. A process crash can leave this private temporary copy until OS temp cleanup; the reader does not sweep other files automatically.

Each source file is capped at 32 MiB; the WASM recovered memory image has a separate 32 MiB limit (a combined logical database beyond this limit remains unsupported on the WASM path); each metadata blob at 1 MiB; a read at 1,000 rows / 2 MiB metadata; worker at 10 seconds, with at most 2 MiB returned metadata. Abort and timeout terminate the worker before deleting the snapshot. The worker JS heap limit is 128 MiB, but native buffers and WASM linear memory are outside that limit; it is not a hard process-memory limit. The smaller file cap limits input copies and reports oversized files explicitly. No schema migration, source checkpoint or lock acquisition is performed. Python 3 is used only by synthetic test-fixture writers and is not a runtime dependency. No software is installed. Windows and matching native WSL paths are accepted but require platform acceptance; remote SSH/container URI mapping is not implemented.

## Offline acceptance

Synthetic metadata and live synthetic WAL fixtures include native/WASM differential checks across 512/4096/65536-byte pages, uncommitted transactions, rollback/commit, checkpoint/reset, little/big-endian checksums, corrupt/incomplete/stale WAL tails and effective main-header page counts. They cover source DB/WAL/SHM hashes and timestamps, rollback journals, changed snapshots, links, schema changes, malformed wire data, missing/zero/conflicting token fields, duplicate responses, multi-response image batches, SSE conflicts/interruptions, legacy image/wake state and global Chinese/English. Isolated VS Code UI tests use a separate profile and only synthetic files/accounts/transports. No production credentials or real conversation files are used, and no Google requests are sent.
