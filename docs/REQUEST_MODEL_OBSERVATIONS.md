# Model and token records — 0.1.13

The workbench records raw server model declarations; it cannot verify underlying weights or prove that an advertised backend actually served a request. No model aliases, pricing tables, catalog/display-name joins, cross-row fill, proxy or additional inference request are used.

## Available paths

- **Official CLI / IDE local conversations:** the workbench's **Model and token records** button opens an on-demand reader. **Read local records** discovers official CLI / IDE conversation directories on the current extension host when clicked; directory/file pickers are fallback options. Nothing is discovered or read at activation or panel opening. Discovery is bounded to the 20 most recently modified UUID databases (5,000 directory entries per source) and 2,000 generation rows per read, with explicit limited/skipped scope and fixed reason counts (changed, unsupported schema/data, unsafe, unavailable, file size limit). File mtime only selects files; it is not a generation timestamp. Windows UI hosts in WSL workspaces cannot scan Windows home as WSL data; they must run in the native WSL extension host. The selected database's `gen_metadata(idx,data)` is decoded per generation, with response identity used only for deduplication. Data stays in panel memory and is cleared on close; reading again replaces the list. CLI usually uses `~/.gemini/antigravity-cli/conversations`, IDE `~/.gemini/antigravity/conversations`; the CLI directory respects GEMINI_CLI_HOME. Unknown schema/fields remain explicit. **Requested model field number is unverified and therefore not implemented**: it displays Not provided with an explanation. Display label #21 is ignored.
- **Existing direct image requests:** task details retain requested ID and one returned observation for each attempted batch HTTP response. Root `model`, `modelVersion` and wrapped `response.model`, `response.modelVersion` are inspected independently. Transport failures have missing response metadata. No additional account/project/catalog/generation request is introduced by this feature.
- **Existing wake requests:** instance details show requested ID and the same raw fields across SSE frames. Distinct declarations are retained as conflicts rather than overwritten; an interrupted stream preserves declarations already received. No additional scheduled run or probe is introduced. Old records without optional metadata show Not provided. If a received result cannot be persisted because another host holds the state lock, the current host retains that result and retries only the guarded state write on the next poll. It never re-sends the request. Changed attempts, terminal rows and expired leases cannot be upgraded to success; losing the in-memory result on host exit remains an unknown outcome.

Different declared strings, including differing root/wrapped/version fields, are marked conflicting declarations; this is not proof of routing failure. Sources remain associated with their raw values. Missing/invalid/conflicting fields are separate. At most two summary values and ten field/value declarations are retained per response; overflow is marked. Invalid field values are not echoed.

Ordinary records and image/wake details use friendly **Requested model**, **Returned model**, and token labels in Chinese and English. Internal field paths are not shown in ordinary details. Local records have an explicitly optional, initially collapsed **Technical details (raw fields)** section; raw provenance is populated only when that section opens and removed from page text when it closes. This presentation does not change the stored field/value evidence.

## Local fields and token semantics

The earlier Tokscale interpretation is withdrawn for token values. It counted usage #1 as system input and reversed #9/#10, but stronger public descriptor evidence identifies #1 as a model enum, #9 as thinking output and #10 as response output. Existing installations before this correction may display inaccurate token values; neither successful wire parsing nor the former synthetic token fixture establishes their semantics.

The root is `CortexStepGeneratorMetadata.chat_model` (#1), with sibling fields `ChatModelMetadata.response_model` (#19, string) and `usage` (#4, `ModelUsageStats`). The bounded reader continues to preserve the #19 string as a returned **declaration**, independently of token interpretation. It does not infer a requested model from the usage model enum or the returned declaration.

| Descriptor field | Wire number | Earlier interpretation / limitation |
| --- | --- | --- |
| model (enum) | #1 | Was incorrectly added to input; never a token count |
| input_tokens | #2 | Cache inclusion is not established; do not label uncached or sum caches into it |
| output_tokens | #3 | Descriptor total; no invented zero or derived historical total |
| cache_write_tokens | #4 | Earlier parser omitted it |
| cache_read_tokens | #5 | Distinct from cache writes |
| thinking_output_tokens | #9 | Earlier text label was reversed |
| response_output_tokens | #10 | Earlier reasoning label was reversed |
| response_id | #11 | Bounded hash for same-session deduplication; not a network request counter |

The ordinary reader applies the confirmed root/chat/usage contract to structurally compatible records. `usageInterpretation: verified` means the field contract was recognized, not that a historical producer version was identified. The earlier requirement for a per-record producer version is withdrawn: a third-party reader's wrong interpretation is not evidence that Google reused the protobuf field numbers. No field magnitude, enum value or output arithmetic selects a contract. Truly absent, malformed, conflicting or unsafe integer values remain unknown; missing fields never become zero.

The URI is represented by an opaque digest and a safe basename or anonymous label, never a raw path, inferred Git repository or cloud project. ## Overview, details and export

The records page shows a compact usage overview and a directly visible record list on the same page. The first read includes **All read records**; refresh preserves the user's chosen time range and still-valid model/workspace filters. Reading and refresh have distinct button labels, with filters and export in one wrapping toolbar. Daily trends, source scope and longer explanations are collapsed by default.

Today / last 7 / last 30 days remain local calendar days including today, using the host timezone and visible date boundaries. A time range with no records has a clear empty message and no Unknown token cards. When a wider range contains records, **View all N records** changes only the time range and preserves model/workspace choices. Missing dates are identified separately; records with missing token values retain honest coverage indicators. Future timestamps remain excluded and cannot inflate the recovery-button count. Repeating an unchanged filter does not reread, reset pagination or cancel an export. No timestamp conversion or metadata parser was changed for this UI correction. The isolated VS Code fixture reads synthetic SQLite metadata through the production reader and tests Los Angeles time, real narrow-window rendering, refresh, pagination and export.

Metrics count **generation records**, not network requests. Deduplication stays within the client and opaque database identity, using bounded response identity or a generation index fallback. Per-field token aggregates report known coverage, missing/invalid/conflicting values, and safe-integer overflow. Input, cache write, cache read, text output, thinking output and total output remain separate; no cost or grand token total is invented. Model conflicts are one category, never duplicated across individual declarations. Workspace filtering appears only for a unique verified safe label; paths and account attribution are not ordinary fields.

The **record list** shows time, returned model and token observations, with safe local session ordinals. It renders 60 rows at a time with **Show more** and preserves the complete host-memory selection for export. Technical provenance remains collapsed and is populated only on explicit expansion.

The single export action selects CSV or JSON and opens Save As for the current filtered host-memory snapshot; it never accepts content or destinations from webview messages. Cancellation or refused replacement writes nothing. Existing files require one explicit application replacement confirmation; the native Save As dialog can also present a platform overwrite prompt, which the VS Code API does not expose or disable. The approved target identity/revision and all parent directories are rechecked, data is staged privately in the same directory, then synced and atomically linked/replaced. The final verification and rename cannot be made a portable conditional transaction against a non-cooperating process; success at link/rename is the commit point. Save targets are restricted to regular local CSV/JSON files, with no symlinks/hardlinks. Raw response IDs, session UUIDs, source paths, prompt tables, credentials and protobuf paths are excluded. CSV cells are quoted and formula prefixes are neutralized, including leading whitespace/control. Unverified token observations stay empty rather than becoming zero. Both formats freeze the observed-through instant and local date boundaries and include the bounded-read file/record/skip/limit scope; neither claims complete history. Export does not read the source again or send a model request.

## Safe snapshot and limits

The reader opens source DB and optional WAL with read-only file handles, never opens source SHM and never connects SQLite to the original path. It checks ownership, regular-file type, no links, handle/path identity and size/mtime/ctime before and after copying. Nonempty rollback journals or changing snapshots fail closed. On-demand directory imports retry changed snapshots once, sequentially; every attempt uses and cleans its own private snapshot. It copies DB/WAL bytes to a private 0700 temporary directory (0600 files), queries only `gen_metadata(idx,data)`, optional `steps(idx,metadata)`, and the `trajectory_metadata_blob(id=main,data)` row in a bounded, cancellable worker, closes and removes the copy. The worker detects built-in `node:sqlite` at runtime; older hosts use the packaged sql.js 1.14.2 WASM, with no Python, downloads or native ABI modules. WASM replays only complete committed WAL transactions after checking page size, salts and cumulative checksums, then reads a self-contained private memory image. Invalid frame tails end recovery at the last valid commit, as specified by SQLite; invalid WAL headers fail closed. SQLite may touch only the private copy's SHM. Raw prompt tables are not decoded, queried, emitted or persisted, although database bytes necessarily pass through the temporary file snapshot. A process crash can leave this private temporary copy until OS temp cleanup; the reader does not sweep other files automatically.

Each source file is capped at 32 MiB; the WASM recovered memory image has a separate 32 MiB limit (a combined logical database beyond this limit remains unsupported on the WASM path); each metadata blob at 1 MiB; a database read at 1,000 generation rows, 2,000 step metadata rows and 2 MiB combined raw metadata; worker at 10 seconds, with at most 2 MiB returned metadata. Abort and timeout terminate the worker before deleting the snapshot. The worker JS heap limit is 128 MiB, but native buffers and WASM linear memory are outside that limit; it is not a hard process-memory limit. The smaller file cap limits input copies and reports oversized files explicitly. No schema migration, source checkpoint or lock acquisition is performed. Python 3 is used only by synthetic test-fixture writers and is not a runtime dependency. No software is installed. Windows and matching native WSL paths are accepted but require platform acceptance; remote SSH/container URI mapping is not implemented.

## Offline acceptance

Synthetic metadata and live synthetic WAL fixtures include native/WASM differential checks across 512/4096/65536-byte pages, uncommitted transactions, rollback/commit, checkpoint/reset, little/big-endian checksums, corrupt/incomplete/stale WAL tails and effective main-header page counts. They cover source DB/WAL/SHM hashes and timestamps, rollback journals, changed snapshots, links, schema changes, malformed wire data, missing/zero/conflicting token fields, duplicate responses, multi-response image batches, SSE conflicts/interruptions, legacy image/wake state and global Chinese/English. Isolated VS Code UI tests use a separate profile and only synthetic files/accounts/transports. No production credentials or real conversation files are used, and no Google requests are sent.

On Windows, the synthetic SHM preservation check uses a read-only mapping to retain the whole-file hash while SQLite holds byte-range locks. The active-writer tests assert that the product opens only the original DB/WAL with read-only flags, never the original SHM. A source name disappearing after copying is classified as a changed source even when the held handle's timestamps do not change; the race test requires the intended mutation to succeed rather than accepting an unrelated I/O failure.

Windows race-fixture boundary: after the complete synthetic WAL has been copied, its Windows fixture handle is released and its old descriptor stat is retained while an actual on-disk replace/remove is performed. This models the stale-handle/name race; active-writer source access remains separately tested. It is not acceptance of a real official Windows active-WAL session.

## Validation scope

The actual production webview is checked with synthetic CLI/IDE databases in a separate VS Code profile: initial all-record reading, same-page totals and list, local-time filtering, empty-period recovery, refresh, pagination, export and Chinese/English rendering. Missing data remains explicit. These checks do not establish real backend model weights or every official producer/platform variant. See [0.1.13 validation scope](VALIDATION_0.1.13.md).
