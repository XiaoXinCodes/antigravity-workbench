# 故障排查与问题反馈

先从命令面板打开“Antigravity Workbench: 高级排障…”，选择检查扩展运行位置，确认两个扩展的宿主、安装位置和当前状态，再按错误码处理。不要通过删除账号、官方登录文件或会话历史来试错。

## 常见问题

| 现象 / 错误 | 建议操作 |
| --- | --- |
| 账号列表仍在，但切换不可用 | 查看是否有待恢复操作、另一窗口占用、存储能力不足或宿主不一致；按恢复入口处理 |
| `OFFICIAL_COMPONENT_RESTART_UNAVAILABLE` | 官方组件没有可用的受支持重启能力；检查扩展是否激活及其兼容性，收集版本与错误码 |
| `CLOSE_OTHER_AGY_PROCESSES` | 结束其他相关任务或窗口后重新检查；不要随意终止身份不明的进程 |
| 账号来自另一宿主 | 回到原保存位置，或通过加密导入迁移，不直接复制存储数据库 |
| 配额显示“上次结果”或要求重新授权 | 先查看同步时间和卡片错误；旧结果不是刚刚成功查询。需要时通过 OAuth 重新授权 |
| `IMAGE_DIRECT_AUTH_REQUIRED` / `IMAGE_DIRECT_MODEL_UNVERIFIED` | 检查当前官方登录、保存账号与图片模型是否一致且可用 |
| `IMAGE_DIRECT_RESOURCE_EXHAUSTED` / HTTP 429 | 查看有无明确原因和等待提示；没有细节时不能认定额度耗尽，不重复生图来测试 |
| `IMAGE_DIRECT_RESPONSE_INVALID` / HTTP 200 无图 | 提供操作编号和结构诊断；HTTP 成功不等于有可保存图片 |
| `IMAGE_DIRECT_OUTCOME_UNKNOWN` | 请求可能已到达服务端；先检查输出与操作记录，再决定是否另行提交 |
| 图片已保存，但日志或记录失败 | 先保留并验证图片；记录保存失败不是重新生成的理由 |
| 保存日志失败 | 区分读取、预览、选择目录和保存阶段；换用当前宿主可写的新文件名，保留错误码 |

## 高级排障：图片端点

默认使用 Daily（`daily-cloudcode-pa.googleapis.com`），正常生图无需修改。VS Code 用户设置 **Antigravity Workbench · 高级排障** 中的 `antigravityAccounts.images.endpoint` 保留 Production（`cloudcode-pa.googleapis.com`）作为手动诊断覆盖。

Production 的图片请求稳定性尚未验证；已有 429 的原因不明，不能据此认定它永久不可用，也不能保证切换后能解决问题。修改设置本身不发请求；相关 project 与保存账号模型需在所选端点重新核验，既有任务不会转到另一端点，失败不自动重试或回退。

先查看本机操作记录或已开启的调试日志中的端点与固定主机名，再结合错误码排查。不要为了试端点反复生图；完成诊断后恢复默认 Daily。

```text
操作入口与最少复现步骤：
预期结果：
实际结果与固定错误码：
操作编号、发生时间（如有）：
是否保留了部分结果：
```

如需日志，开启调试后只复现必要的一次操作，关闭，再预览并导出；操作本身若会生成图片或切换账号，仍按界面的正常确认处理。截图只包含问题所需区域，不必提供账号邮箱或私人内容。不要附凭据、加密账号包的密码或原始服务响应。

提交前检查文字与附件，移除账号、私人路径及无关内容。疑似凭据泄露或其他安全漏洞按 [安全报告流程](../SECURITY.md) 私下处理，不在普通 Issue 中公开细节。

## 图片模型目录与 Pro 排查

当前账号已有模型时，“重新检查当前账号”仍可点击；查询中禁用重复点击。它使用官方 Hub 的 GetAvailableModels 空请求，不声称强制清除 Hub 缓存。已保存账号重新检查则绕过本地五分钟目录缓存。刷新不会生成图片，也不会弹出生图确认。

从命令面板打开“Antigravity Workbench: 高级排障…”，选择“诊断图片目录（不生图）”，无需开启调试模式。工作台主动显示独立查询进度和结果区域，无需打开文件。可关闭该区域，迟到响应不会重新打开；关闭工作台后重开仍能查看本窗口保留的结果，重载后不保留。重复执行受查询中和停止状态约束。诊断使用现有授权流程（已保存令牌过期时可走原有安全刷新），不新建 OAuth、不切换官方账号、不生成图片。

诊断先核验当前 Hub 身份，再唯一匹配同宿主的已保存账号，比较 Hub 目录和所选 Daily/Production 端点的同账号直连目录。匹配不了同账号就停止直连，绝不会借用另一号。查询期间身份、账号记录或端点发生变化会丢弃对照结果；超时或查询失败可再次点击。只显示来源、端点、查询时间、可知缓存信息、图片 model IDs、Pro 相关 disabled 声明和差异。不显示邮箱、token、project 原值、提示词、完整响应或任意异常正文，不写诊断文件、不自动上传。

“未查询”“查询失败”“未列出”都不能推断没有 Pro 权限；disabled=false 或目录未声明禁用也不能保证真实生成成功。Hub 内部缓存年龄和管理端点未提供时明确显示未知。新的合法图片模型按已核验目录成员资格绑定，请求保留原始 ID（包括 gemini-nano-banana-2.1），不会把文本模型或静态名称列表当作图片权限。
