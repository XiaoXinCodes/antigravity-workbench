# 0.1.16 验证范围

## 变更与边界

基于 main `b041272917967dfcdd2f7b0a1a09b837cc1882b3`，改善图片与额度诊断交互，版本和发行资产路径更新为 0.1.16；同步本项目两处请求 User-Agent 与离线协议样本的版本号。

图片 403 只有无冲突、明确结构化 reason `VALIDATION_REQUIRED`、`PERMISSION_DENIED` 或 `ACCESS_DENIED` 才分别显示账号验证或权限说明。通用 status `PERMISSION_DENIED` 只保留为高级诊断证据；details 缺省、空数组、畸形、无 reason 或未知 reason，以及自由文本验证挑战均不足以确定分类。其他已有明确服务端 reason 保持原有分类。不从消息、验证链接或社区说法推断账号封禁。

重试建议与额度恢复信息独立展示；保留 Retry-After 和 RetryInfo 的差别，未提供恢复时间时保持未知，不从等待值计算精确恢复时刻。提示不会自动重试、换号、登录或打开网页。账号额度与模型目录传输继续不读错误正文，因此这两条路径的未知 403 不会被升级为验证或权限结论。

沿用图片错误 16 KiB、有效 UTF-8、JSON、最多 24 条详情及固定字段约束；不保存原始敏感响应、令牌、邮箱或验证 URL，不新增验证链接入口。普通界面使用固定中英文说明，内部字段留在高级调试中。旧任务仅调整显示，不迁移账号、草稿、图片或历史数据，也不改变单次请求行为。

## 验证方法

使用合成账号、离线传输、隔离 HOME / USERPROFILE 和 VS Code 用户数据。检查 `npm run check`、许可、发布安全与包文档回归，构建 VSIX 并运行 Release 与 Marketplace 离线校验。定向 fixture 覆盖明确验证与权限、通用 status 配验证文字、缺省/空/畸形/未知 details、恶意 URL、冲突与缺省等待、重复与迟到结果、旧数据保持。

生产界面另用 `node scripts/render-diagnostics.cjs` 检查中英文、440/1000px 和四类诊断状态；实际 VS Code 截图套件覆盖相同诊断并验证高级调试默认收起，图片和定时模型请求数为零。宿主检查包括启动、额度与全局语言交互。

本机 Linux 沙箱将 `/` 与 `/tmp` 所有者映射为 UID 65534，原始 main 也触发相同的存储保护失败；默认 umask 077 使一个故意创建宽权限文件的夹具失去预期条件。最终本机门禁在正常所有权视图和 CI 常用 umask 022 下执行，不修改或跳过安全保护。Windows 专属测试在 Linux 沿用原有跳过规则，三平台结果以精确 PR 提交的 GitHub Actions 为准。
